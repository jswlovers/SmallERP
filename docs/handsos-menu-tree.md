# 핸드SOS(HandSOS) 메뉴 트리 분석 및 SmallERP 대응표

조사일 2026-09-20. 대상: https://www1.handsos.com/ (→ 302로 https://www.handsos.com/ 이동, 로그인 전 화면)

## 0. 조사 범위와 신뢰도

| 출처 | 확인한 것 | 신뢰도 |
|---|---|---|
| **로그인 후 실제 프로그램 화면** (사용자가 제공한 계정으로 로그인, 읽기 전용) | 좌측 메뉴 10개 그룹과 하위 메뉴 105개, 상단 바, 대시보드, 기초설정·예약판·자동문자 화면 | **확정** (DOM에서 직접 추출) |
| 공개 웹사이트 | 상단·하단 메뉴 구조와 URL, 로그인 방식(회사코드+사용자ID+비밀번호), 가입 조건 | 확정 |
| 공식 유튜브 재생목록(영상 7개) 자동 자막 | 영상 1·2·4에서 각 기능의 사용 흐름·동작 규칙 | 참고(음성인식 오류 있음) |

조사 방법·주의: 로그인은 자동 브라우저로 했고 메뉴 이동과 화면 읽기만 했다(저장·삭제·문자 발송 없음). 매장의 고객 정보·사업자 정보는 문서에 옮기지 않았다. 캡처 이미지도 삭제했다.

### 2-3. 영상 자막에서 확인한 동작 규칙
- 네이버 예약 연동 후에는 **핸드SOS가 기준(원본)**. 파트너센터에서 바꾼 휴무·가능시간은 일정 시간 후 핸드SOS 값으로 덮어써진다.
- 전화 예약을 핸드SOS에 넣으면 같은 시간이 네이버에서 자동 차단된다. 핸드SOS에서 취소하면 네이버도 취소된다.
- 네이버페이 선결제·현장결제가 연계된 예약은 시간 변경 불가(취소 후 재예약).
- 매출 입력(이용 완료) 시 네이버 이용 완료가 되어 고객이 리뷰를 쓸 수 있다. "이용 완료" 시점은 "시술중 시/매출 입력 시" 중 선택.
- 이름+휴대폰이 일치하지 않는 네이버 예약은 "손님"으로 들어오고, 매출상세목록에서 기존 고객으로 매칭·이동한다.
- 디자이너별 네이버 매칭은 1:1. 직원 등록에 디자이너 이름이나 상품 이름을 등록해 매칭한다.
- 예약 알림을 담당 디자이너에게도 문자로 보낸다(네이버에는 없는 기능). 노쇼가 잦은 고객은 표시해 두면 네이버 예약 알림에 검정색으로 뜬다.
- 키오스크: 회원 검색(전화번호) → 담당자 → 큰 메뉴/하위 메뉴 → "지금 결제하기" 또는 "시술 후 결제하기", 회원 등록(개인정보 동의), 회원 없이 **간편 접수**(대기 접수 알림).
- 정액권 등록 예: 결제금액 50만원 → 사용가능금액 55만원(보너스) + 유효기간. 회원권은 횟수(예: 5회권) 차감.

## 4. SmallERP 메뉴(IA) 개선 제안

현재 탭: 대시보드 · 예약 · 고객 · 결제 · 문자 · 통계 · 설정. 핸드SOS의 구성(고객 / 예약 / 매출·결제 / 문자·마케팅 / 통계 / 설정)과 거의 같다. 아래 하위 메뉴를 채우는 것을 권한다.

```
대시보드
예약     ├ 일별 목록(현재) ├ 주간 타임테이블(추가) ├ 예약 통계(추가) └ 네이버 예약 설정(추가)
고객     ├ 목록/검색(현재) ├ 휴면·이탈 고객(추가) ├ 등급·포인트 규칙(추가) └ CSV 이전(현재)
결제     ├ 결제 등록·내역(현재) ├ 일 마감/정산(추가) └ 선불권 관리(추가)
문자     ├ 발송(현재) ├ 템플릿(현재) ├ 자동 규칙(현재) └ 발송 내역(현재)
통계     ├ 매출(현재) ├ 기간 비교(추가) └ 고객 분석(추가)
설정     ├ 시술(현재) ├ 직원(현재) ├ 내 계정(현재) └ 문자 충전(현재)
```

우선순위 제안(영상에서 확인된 "처음 사용자 기초 설정" 흐름을 먼저 맞추면 온보딩이 같아진다): ⓪ 기초 등록(시술 분류/상세, 회원권, 정액권, 포인트 적립) ① 주간 타임테이블·휴무/브레이크타임 ② 휴면 고객 목록 + 재방문 안내 자동화 연결 ③ 일 마감 ④ 기간 비교 통계 ⑤ 등급 자동 승급·포인트. 이후 외부 계약이 필요한 항목(카드 단말, 네이버 API, 알림톡)을 진행한다.
