## 1. 매장 직원 화면 — `/index.html`

정적 HTML(`public/index.html`) + SPA 스크립트(`public/app.js`)로 구현되며, 로그인 전에는 `#login`, 로그인 후에는 `#app`(헤더 + 탭 네비게이션 + `<main id="view">`)이 표시됩니다.

### 로그인/가입
| 화면 | API | 구현 파일 |
|---|---|---|
| 로그인 | `POST /api/auth/login` | `src/routes/auth.js` |
| 신규 매장 등록 | `POST /api/auth/register` | `src/routes/auth.js` |
| 내 정보 조회(부팅 시) | `GET /api/me` | `src/routes/auth.js` |
| 비밀번호 변경 | `POST /api/me/password` | `src/routes/auth.js` |

로그인 성공 시 JWT를 로컬에 저장하고, 이후 모든 `/api/*` 요청(공개 라우트 제외)에 `Authorization` 헤더로 첨부합니다(`src/app.js`의 `onRequest` 훅에서 검증).

### 탭 구성 (`public/app.js`의 `TABS` 배열, `public/views/*.js`)
| 탭 키 | 이름 | 구현 파일 | 주요 내용 |
|---|---|---|---|
| `dash` | 대시보드 | `views/dash.js` | 오늘 매출·예약·대기 현황 요약 |
| `resv` | 예약 | `views/resv.js` | 캘린더/타임테이블, 예약 상태 관리, 네이버 예약 표시 |
| `wait` | 대기 | `views/wait.js` | 셀프 접수 대기열(키오스크에서 등록된 대기자 포함) |
| `cust` | 고객 | `views/cust.js` | 고객 검색·등록·이력·CSV 가져오기/내보내기 |
| `pay` | 결제 | `views/pay.js` | 매출 등록, 결제수단별 할인, 정액권/회원권/포인트 차감 |
| `prod` | 상품 | `views/prod.js` | 시술 분류·메뉴, 제품·매입처·재고 |
| `msg` | 문자 | `views/msg.js` | 자동 문자 발송 규칙 설정, 발송 이력 |
| `stats` | 통계 | `views/analysis.js` | 매출·고객 동향 분석 |
| `cash` | 입출금 | `views/cash.js` | 입출금 관리 |
| `shop` | 매장 | `views/shop.js` | 직원 관리, 근무·휴무·예약금지 시간대 |
| `set` | 설정 | `views/set.js` | 솔루션 간편설정, 온라인 예약 정책, 매장 공개 링크 발급 |

각 탭 모듈은 `공용 유틸`(`public/core.js`, `public/views/crud.js`)을 통해 REST API(`src/routes/*.js`)를 호출하는 구조로 통일되어 있습니다.

## 2. 셀프 접수 키오스크 — `/kiosk.html`

매장 내 태블릿 등에서 직원 로그인 상태로 열어두는 화면(`public/kiosk.html` + `public/kiosk.js`). 매장 직원 인증(JWT)이 필요합니다.

| 동작 | API |
|---|---|
| 로그인 상태 확인 | `GET /api/me` |
| 전화번호로 고객 조회 | `GET /api/customers?q=<phone>` |
| 시술/담당자 목록 조회 | `GET /api/services`, `GET /api/staff` |
| 신규 고객 등록(개인정보 동의 체크) | `POST /api/customers` |
| 대기 접수 등록 | `POST /api/standby` |

접수된 대기자는 직원 화면의 "대기"(`wait` 탭) 및 우측 매장현황판에 반영됩니다.

## 3. 고객 온라인 예약 — `/book.html`

매장 직원 로그인과 완전히 분리된 고객 전용 페이지. 매장별 공개 코드(`?s=<코드>`)로 접근합니다.

- **서버 렌더링**: `src/routes/pages.js`가 요청 시 매장 정보·시술·담당자·예약 정책을 SSR(`#ssr` 섹션)로 미리 채워, 검색엔진이나 JS를 실행하지 않는 크롤러도 매장 정보를 읽을 수 있습니다.
- **클라이언트 동작**: `public/book.js`가 로드되면 `#ssr`은 사라지고 실제 예약 UI(휴대폰 인증 → 시술 선택 → 담당자 지정(필수) → 날짜/시간 선택 → 예약)로 대체됩니다.

| 동작 | API | 구현 파일 |
|---|---|---|
| 매장/시술/담당자/정책 조회 | `GET /api/public/:code/info` | `src/routes/public.js` |
| 빈 시간 조회 | `GET /api/public/:code/availability` | `src/routes/public.js` |
| 인증번호 발송 | `POST /api/public/:code/otp/request` | `src/routes/public.js` |
| 인증번호 확인(로그인/가입) | `POST /api/public/:code/otp/verify` | `src/routes/public.js` |
| 내 정보 조회/수정 | `GET`/`PATCH /api/public/:code/me` | `src/routes/public.js` |
| 내 예약 목록/생성/취소 | `GET /api/public/:code/my-reservations`, `POST /api/public/:code/reservations`, `POST /api/public/:code/reservations/:id/cancel` | `src/routes/public.js` |

인증·예약의 실제 도메인 로직은 라우트가 아닌 `src/public-service.js`에 있으며, AI 예약 도우미(4번)도 같은 함수를 공유합니다. 이 라우트들은 전역 JWT 훅에서 제외되어 자체적으로 고객 토큰(`req.user.cust`)을 검증합니다.

## 4. AI 예약 도우미 — `/chat.html`

`book.html`과 같은 매장 공개 코드로 접근하는 대화형 예약 화면(`public/chat.html` + `public/chat.js`).

- 서버: `src/routes/aiChat.js`가 `POST /api/public/:code/chat`을 처리하며, `src/ai/bookingAgent.js`가 Claude API(도구 호출: `getShopInfo`, `getAvailability`, `requestOtp`, `verifyOtp`, `listMyReservations`, `createReservation`, `cancelReservation`)를 실행합니다.
- `ANTHROPIC_API_KEY`가 설정되지 않은 매장에서는 503으로 안전하게 비활성화됩니다.
- 3번(`book.html`)과 동일한 `src/public-service.js` 로직을 도구로 호출하므로, 폼 예약과 정책이 어긋나지 않습니다.
- ChatGPT Custom GPT Actions에서 같은 예약 기능을 쓸 수 있도록 OpenAPI 스펙을 별도로 제공합니다([docs/booking-api-openapi.json](booking-api-openapi.json)).

## 5. 플랫폼 관리자 — `/admin.html`

SmallERP 운영사가 가입된 매장들을 관리하는 화면(`public/admin.html` + `public/admin.js`, 매장 직원 화면과는 별도 로그인). `src/bootstrap.js`가 서버 기동 시 `.env`의 `ADMIN_LOGIN`/`ADMIN_PASSWORD`로 관리자 계정을 생성·갱신합니다.

| 동작 | API |
|---|---|
| 관리자 로그인 | `POST /api/admin/auth/login` |
| 관리자 비밀번호 변경 | `POST /api/admin/password` |
| 전체 현황 조회 | `GET /api/admin/overview` |
| 매장 목록 조회 | `GET /api/admin/shops` |
| 매장 정보 수정(활성/비활성 등) | `PATCH /api/admin/shops/:id` |
| 매장 문자 발송 잔액 충전 | `POST /api/admin/shops/:id/charge` |
| 매장 사장 비밀번호 초기화 | `POST /api/admin/shops/:id/reset-owner-password` |
| 관리자 작업 로그 조회 | `GET /api/admin/audit` |

민감한 조작(충전, 비밀번호 초기화, 매장 상태 변경)은 `src/audit.js`를 통해 감사 로그로 남습니다.

## 6. 인증 방식 정리

| 화면 | 토큰 종류 | 발급 API | 검증 위치 |
|---|---|---|---|
| 매장 직원 화면 · 키오스크 | 직원 JWT(`sid`, `shop`) | `POST /api/auth/login` | `src/app.js` 전역 `onRequest` 훅 |
| 고객 온라인 예약 · AI 예약 도우미 | 고객 JWT(`cust`, `shop`) | `POST /api/public/:code/otp/verify` | `src/routes/public.js`의 `custAuth` |
| 플랫폼 관리자 | 관리자 JWT | `POST /api/admin/auth/login` | `src/routes/admin.js` |
| 네이버 예약 웹훅 | 공유 시크릿 헤더(`X-Webhook-Secret`) | 해당 없음(사전 발급된 값) | `src/routes/reservations.js` |

세 종류의 토큰은 서로의 API를 호출할 수 없도록 각 검증 로직에서 필드(`sid`/`cust`/관리자 여부)를 확인합니다.
